# Gapwise Gap Agent V1 migration

## Objective

Run a real Python ADK Gap Agent against the versioned `GapAssessmentV1` contract while preserving the current deterministic ranker as a zero-cost fallback.

## Inputs

- One project-scoped graph snapshot containing node and edge identifiers.
- One existing scoped Context Pack containing selected evidence excerpts and durable preferences.
- No direct Firestore, Cloud Storage, Calendar, or broad retrieval access from the Gap Agent.

## Output

The ADK model returns the compact `GapSelectionDraftV1`: one prevalidated candidate identifier (or `null`), a compact rationale, and escalation signals. The service merges that semantic selection with the deterministic candidate scaffold and validates the final `GapAssessmentV1`. The model never regenerates graph paths, evidence IDs, or suppression state, and it must not emit private reasoning.

## Runtime modes

- `deterministic` (default): no ADK/Gemini call.
- `shadow`: call ADK, validate and compare its selection, but preserve the deterministic product result.
- `live`: use a validated ADK selection; fall back deterministically on timeout, transport failure, invalid schema, invalid graph references, or an unavailable model.

`GAPSWISE_DEMO_MODE=true` always forces deterministic mode and records no fake live trace.

## Evaluation

- Reuse the 15-case CareerGap Golden Set and its deterministic code metrics.
- Compare a cheap, balanced, and strong Gap configuration through environment-controlled model and thinking settings.
- Begin live inference with two cases and a bounded output/token budget.
- Do not lower existing quality gates.

## Observability and privacy

Record run ID, agent, model, thinking level, token counts, latency, estimated cost when configured, validation, confidence, escalation, compact counts, and deterministic/live agreement. Never record prompts, raw Context Packs, document contents, credentials, tokens, or chain-of-thought.

## Rollout

The feature flag is server-side and defaults to deterministic. Shadow and live modes require explicit environment configuration. The checked-in Cloud Build configuration carries the flag but keeps it deterministic. No deployment is included in this implementation.
